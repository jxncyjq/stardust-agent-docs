## 一、设计依据

### 1.1 参考来源

| 参考模块 | 核心能力 | Legion 映射 |
|----------|----------|-------------|
| `tools/lib.rs` | 全局工具注册表、执行入口、权限检查 | 工具注册中心 |
| `tools/lane_completion.rs` | 车道补全工具 | 工作流补全工具 |
| `tools/pdf_extract.rs` | PDF 提取 | 文档解析工具 |
| `commands/lib.rs` | 139 项斜杠命令规范（`SLASH_COMMAND_SPECS`）+ 来源分类 | Agent 内置命令 |
| `plugins/lib.rs` | 插件清单、子进程工具执行 | 自定义技能 |
| `plugins/hooks.rs` | Pre/PostToolUse 钩子 | 工具生命周期钩子 |

### 1.2 设计目标

1. **工具注册与发现** — 统一的工具定义和注册机制
2. **技能可插拔** — 运行时按需加载/卸载技能
3. **安全执行** — 多层权限检查 + 沙箱隔离
4. **可扩展** — 支持内置工具、技能、MCP、插件多种扩展方式

## 二、工具系统架构

```
┌──────────────────────────────────────────────────────────────┐
│                      工具与技能系统                            │
│                                                              │
│  ┌────────────────┐  ┌──────────────┐  ┌─────────────────┐  │
│  │  GlobalTool    │  │  Skill        │  │  SlashCommand   │  │
│  │  Registry      │  │  Registry     │  │  Registry       │  │
│  │  (内置工具)     │  │  (可插拔技能)  │  │  (内置命令)     │  │
│  └───────┬────────┘  └──────┬───────┘  └────────┬────────┘  │
│          │                  │                    │            │
│  ┌───────┴──────────────────┴────────────────────┴────────┐  │
│  │                  ToolExecutor                          │  │
│  │  统一执行入口：权限检查 → 工具查找 → 执行 → 结果返回     │  │
│  └────────────────────────┬───────────────────────────────┘  │
│                           │                                  │
│  ┌────────────────────────┴───────────────────────────────┐  │
│  │              扩展来源                                   │  │
│  │  Builtin (内置) │ Skills (技能包) │ MCP (外部服务)      │  │
│  │  Plugin (插件)  │ Adapter (适配器) │                    │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

### 统一执行流程

```
ToolExecutor.execute(tool_name, input)
  │
  ├── 1. 查找工具
  │     内置注册表 → 技能注册表 → MCP 注册表 → 插件注册表
  │     未找到 → ToolNotFound 错误
  │
  ├── 2. Pre-Hook
  │     执行前置钩子 → 可拒绝/修改输入
  │
  ├── 3. 权限检查
  │     按工具类型匹配权限级别 → 可拒绝
  │
  ├── 4. 执行
  │     调用对应实现 → 超时/错误处理
  │
  ├── 5. Post-Hook
  │     执行后置钩子 → 副作用处理
  │
  └── 6. 返回结果
```

## 三、工具注册与执行框架

### 3.1 工具规范定义

参考 claw-code `tools/lib.rs` 的 `ToolSpec`：

```rust
struct ToolSpec {
    name: String,              // 工具名（全局唯一）
    description: String,       // 工具描述
    input_schema: Value,       // JSON Schema 定义输入结构
    source: ToolSource,        // 来源
    required_permission: PermissionMode,  // 所需权限级别
    is_read_only: bool,        // 是否只读
}

enum ToolSource {
    Builtin,                   // 内置
    Skill { skill_id: String },
    McpServer { server_name: String },
    Plugin { plugin_id: String },
    Adapter { adapter_type: String },
}
```

### 3.2 全局工具注册表

参考 claw-code 的 `GlobalToolRegistry`：

```rust
struct GlobalToolRegistry {
    tools: BTreeMap<String, ToolSpec>,
    executors: HashMap<String, Box<dyn ToolExecutable>>,
}

impl GlobalToolRegistry {
    fn register(&mut self, spec: ToolSpec, executor: Box<dyn ToolExecutable>) {
        self.tools.insert(spec.name.clone(), spec);
        self.executors.insert(spec.name.clone(), executor);
    }

    fn list_for_model(&self) -> Vec<ToolDefinition> {
        self.tools.values()
            .map(|spec| ToolDefinition {
                name: spec.name.clone(),
                description: spec.description.clone(),
                input_schema: spec.input_schema.clone(),
            })
            .collect()
    }

    async fn execute(&self, name: &str, input: Value, ctx: &ExecutionContext) -> ToolResult {
        let spec = self.tools.get(name)
            .ok_or(ToolError::NotFound(name.into()))?;

        let executor = self.executors.get(name)
            .ok_or(ToolError::NoExecutor(name.into()))?;

        executor.execute(input, ctx).await
    }
}
```

## 五、技能系统设计

### 5.1 技能定义

技能是工具的**可插拔组合包**，在运行时按需加载：

```rust
struct Skill {
    id: String,
    name: String,
    version: String,
    description: String,
    tools: Vec<ToolSpec>,           // 技能提供的工具
    commands: Vec<SlashCommandSpec>, // 技能提供的命令
    hooks: Vec<HookSpec>,           // 生命周期钩子
    dependencies: Vec<String>,      // 依赖的其他技能
    permissions: Vec<Permission>,   // 技能需要的额外权限
}
```

### 5.2 技能来源

参考 claw-code `plugins/lib.rs` 的三种类型：

| 来源 | 说明 | 加载方式 |
|------|------|----------|
| **Builtin（内置）** | Legion 官方提供的技能 | 编译时内置 |
| **Marketplace（市场）** | 从技能市场安装 | Git URL / 包下载 |
| **Custom（自定义）** | 用户自行开发 | 本地路径 / Git URL |

### 5.3 技能生命周期

参考 claw-code `plugin_lifecycle.rs` 的状态机：

```
Unconfigured → Validated → Installing → Installed → Healthy
                                                      │
                                              Degraded │ (健康检查失败)
                                                      ▼
                                              Failed → Restarting → Healthy
                                                │
                                                ▼
                                              Stopped
```

### 5.4 技能执行隔离

参考 claw-code 插件通过子进程执行工具的隔离设计：

```yaml
skill_execution:
  isolation: process           # 独立进程执行
  communication: stdin_stdout  # stdin/stdout 通信
  context_passing: env_vars    # 环境变量传递上下文
  timeout: 300s                # 默认超时
  max_memory_mb: 512           # 内存限制
```

```rust
struct SlashCommandSpec {
    name: String,              // 命令名（如 "help"）
    description: String,       // 命令描述

enum CommandSource {
    Builtin,                   // 内置
    InternalOnly,              // 仅内部可用

type CommandHandler = fn(args: &[String], context: &ExecutionContext) -> Result<String>;
```

## 七、Plugin/MCP 扩展

### 7.1 MCP 工具桥接

参考 claw-code `mcp_tool_bridge.rs` 的工具注册桥接：

```rust
struct McpToolBridge {
    servers: BTreeMap<String, McpServerState>,
}

struct McpServerState {
    config: ScopedMcpServerConfig,
    status: McpConnectionStatus,    // Connected/Disconnected/Degraded/Error
    tools: Vec<ManagedMcpTool>,
    connected_at: DateTime,
    last_error: Option<String>,
}

impl McpToolBridge {
    /// 从 MCP 服务器发现的工具名转换为统一格式
    fn normalize_name(server: &str, tool: &str) -> String {
        format!("mcp__{server}__{tool}")
    }

    fn list_connected_tools(&self) -> Vec<ToolSpec> {
        self.servers.values()
            .filter(|s| s.status == McpConnectionStatus::Connected)
            .flat_map(|s| s.tools.iter().map(|t| t.to_tool_spec()))
            .collect()
    }
}
```

### 7.2 MCP 生命周期

参考 claw-code `mcp_lifecycle_hardened.rs` 的 11 阶段生命周期：

```
1. ConfigDiscovery → 2. Validation → 3. Spawning
  → 4. Handshake (initialize) → 5. CapabilityNegotiation
  → 6. ToolDiscovery (tools/list) → 7. ResourceDiscovery
  → 8. Healthy → 9. DegradedGraceful
  → 10. Reconnecting → 11. Terminated
```

每个阶段有独立的错误处理和状态跟踪，阶段间转换有超时保护。

## 八、三原则落地

### 8.1 可观测

| 观测点 | 内容 |
|--------|------|
| 工具调用日志 | 每次工具执行的名称、输入、输出、耗时、是否成功 |
| 技能加载记录 | 技能的安装、加载、卸载事件 |
| MCP 连接状态 | 服务器连通性追踪、工具发现结果 |
| 命令使用统计 | 各命令调用频次、参数分布 |

### 8.2 可治理

| 治理能力 | 实现方式 |
|----------|----------|
| 工具黑名单 | `disallowed_tools` 配置禁止特定工具 |
| 技能审核 | 自定义技能安装前需审批 |
| 命令权限 | 按角色限制可用命令 |
| MCP 服务器白名单 | 仅允许连接已审批的 MCP 服务器 |

### 8.3 可控风险

| 风险 | 控制 |
|------|------|
| 工具滥用 | 每个工具绑定所需权限级别，自动拦截越权调用 |
| 恶意技能 | 自定义技能需审批 + 沙箱隔离执行 |
| MCP 连接泄露 | 超时控制 + 连接数限制 |
| 命令注入 | Bash 校验管线（destructive 检测 + sed 校验 + 路径检测）|
