### 1.2 设计目标

Legion 的权限模型需要比开发工具（claw-code）更复杂：

1. **组织级权限** — 按公司/部门/角色分级
2. **功能权限** — 工具调用、知识库读写、任务委派
3. **数据权限** — 知识域隔离、项目数据隔离
4. **执行安全** — 命令校验、沙箱隔离、工作区边界

## 三、权限模式定义

### 3.1 五级权限模式

参考 claw-code 的 `PermissionMode`（有 `Ord` 递增）：

```rust
#[derive(PartialOrd, Ord, PartialEq, Eq)]
enum PermissionMode {
    ReadOnly,          // 只能读取
    WorkspaceWrite,    // 可在工作区写入
    DangerFullAccess,  // 全系统访问
    Prompt,            // 委托给交互式确认
    Allow,             // 全部放行（仅管理员）
}
```

### 3.2 工具到权限的映射

```rust

impl Default for ToolPermissionMap {
    fn default() -> Self {
        let mut map = BTreeMap::new();

        // 只读工具
        map.insert("read_file".into(), PermissionMode::ReadOnly);
        map.insert("glob_search".into(), PermissionMode::ReadOnly);
        map.insert("grep_search".into(), PermissionMode::ReadOnly);
        map.insert("wiki_search".into(), PermissionMode::ReadOnly);
        map.insert("wiki_read".into(), PermissionMode::ReadOnly);

        // 写入工具（需 WorkspaceWrite 及以上）
        map.insert("write_file".into(), PermissionMode::WorkspaceWrite);
        map.insert("edit_file".into(), PermissionMode::WorkspaceWrite);
        map.insert("wiki_write".into(), PermissionMode::WorkspaceWrite);
        map.insert("wiki_update".into(), PermissionMode::WorkspaceWrite);
        map.insert("task_create".into(), PermissionMode::WorkspaceWrite);

        // 危险工具（需 DangerFullAccess 及以上）
        map.insert("bash".into(), PermissionMode::DangerFullAccess);
        map.insert("team_create".into(), PermissionMode::DangerFullAccess);
        map.insert("subagent_dispatch".into(), PermissionMode::DangerFullAccess);

        map
    }
}
```

### 3.3 权限策略规则

参考 claw-code 的 `allow_rules` / `deny_rules` / `ask_rules`：

```rust
struct PermissionPolicy {
    mode: PermissionMode,                    // 基础模式
    allow_rules: Vec<PermissionRule>,        // 显式允许
    deny_rules: Vec<PermissionRule>,         // 显式拒绝（最高优先级）
    ask_rules: Vec<PermissionRule>,          // 需要交互确认
}

struct PermissionRule {
    tool_name: String,                       // 工具名（支持通配符）
    subject_pattern: Option<String>,         // 作用对象（文件路径/命令等）
    reason: String,                          // 规则说明
}

// 评估流程
impl PermissionPolicy {
    fn authorize(&self, tool: &str, input: &Value) -> PermissionOutcome {
        // 1. deny_rules 检查 → Deny（短路）
        for rule in &self.deny_rules {
            if rule.matches(tool, input) {
                return PermissionOutcome::Deny {
                    reason: rule.reason.clone(),
                };
            }
        }

        // 2. allow_rules 检查 → Allow
        for rule in &self.allow_rules {
            if rule.matches(tool, input) {
                return PermissionOutcome::Allow;
            }
        }

        // 3. ask_rules 检查 → Ask
        for rule in &self.ask_rules {
            if rule.matches(tool, input) {
                return PermissionOutcome::Ask {
                    question: format!("允许 {} 操作？", tool),
                };
            }
        }

        // 4. 模式匹配 → 基于 mode 判定
        let required = TOOL_PERMISSION_MAP.requirements.get(tool)
            .unwrap_or(&PermissionMode::DangerFullAccess);

        if self.mode >= *required {
            PermissionOutcome::Allow
        } else {
            PermissionOutcome::Deny {
                reason: format!("当前权限模式 {:?} 不足，需要 {:?}", self.mode, required),
            }
        }
    }
}
```

### 3.4 权限规则匹配

参考 claw-code 的 `tool_name(subject)` 格式解析：

```rust
impl PermissionRule {
    fn matches(&self, tool_name: &str, input: &Value) -> bool {
        // 1. 工具名匹配（支持通配符 *）
        if !self.wildcard_match(&self.tool_name, tool_name) {
            return false;
        }

        // 2. 如果没有 subject 模式，工具名匹配即通过
        let Some(pattern) = &self.subject_pattern else {
            return true;
        };

        // 3. 从 input 提取匹配对象
        let subject = self.extract_subject(tool_name, input);

        // 4. wildcard 匹配
        self.wildcard_match(pattern, &subject)
    }

    fn extract_subject(&self, tool_name: &str, input: &Value) -> String {
        // 按优先级提取
        if let Some(cmd) = input.get("command").and_then(|v| v.as_str()) {
            return cmd.to_string();
        }
        if let Some(path) = input.get("file_path").and_then(|v| v.as_str()) {
            return path.to_string();
        }
        if let Some(url) = input.get("url").and_then(|v| v.as_str()) {
            return url.to_string();
        }
        if let Some(pattern) = input.get("pattern").and_then(|v| v.as_str()) {
            return pattern.to_string();
        }
        String::new()
    }
}
```

## 四、权限执行门控

### 4.1 PermissionEnforcer

参考 claw-code 的 `permission_enforcer.rs`：

```rust
struct PermissionEnforcer {
    workspace_root: PathBuf,
    allowed_outside_paths: Vec<PathBuf>,
    allowed_commands: Vec<String>,
}

impl PermissionEnforcer {
    fn check(&self, tool: &str, input: &Value, mode: PermissionMode) -> EnforcementResult {
        match mode {
            // Prompt 模式：委托给交互式确认（由上层处理）
            PermissionMode::Prompt => EnforcementResult::Allowed,

            // ReadOnly 模式：拦截所有写入操作
            PermissionMode::ReadOnly if is_write_tool(tool) => {
                EnforcementResult::Denied {
                    reason: "当前为只读模式，不允许写入操作".into(),
                }
            }

            // WorkspaceWrite 模式：检查工作区边界
            PermissionMode::WorkspaceWrite => {
                self.check_workspace_boundary(tool, input)
            }

            // DangerFullAccess 及以上：放行
            _ => EnforcementResult::Allowed,
        }
    }

    fn check_workspace_boundary(&self, tool: &str, input: &Value) -> EnforcementResult {
        let target_paths = self.extract_file_paths(tool, input);
        for path in &target_paths {
            if !path.starts_with(&self.workspace_root)
                && !self.allowed_outside_paths.iter().any(|p| path.starts_with(p))
            {
                return EnforcementResult::Denied {
                    reason: format!("路径 {} 在工作区之外，WorkspaceWrite 模式下不允许", path.display()),
                };
            }
            if is_symlink_escape(path, &self.workspace_root) {
                return EnforcementResult::Denied {
                    reason: format!("路径 {} 通过符号链接逃逸工作区", path.display()),
                };
            }
        }
        EnforcementResult::Allowed
    }
}
```

### 4.2 符号链接逃逸检测

参考 claw-code `file_ops.rs` 的 `is_symlink_escape()`：

```rust
fn is_symlink_escape(target: &Path, workspace_root: &Path) -> bool {
    // 如果是符号链接，解析真实路径
    if target.is_symlink() {
        if let Ok(real) = target.canonicalize() {
            return !real.starts_with(workspace_root);
        }
    }
    false
}
```

## 五、Bash 安全校验管线

### 5.1 六类校验

参考 claw-code `bash_validation.rs` 的完整校验管线：

```
用户命令
  │
  ├── ① 只读模式拦截
  │   检测当前权限级别 → ReadOnly 模式拒绝所有 shell 命令
  │
  ├── ② 破坏性命令警告
  │   匹配 rm -rf / format / dd / mkfs 等模式 → 生成警告
  │
  ├── ③ 权限约束检查
  │   将命令分类为 ReadOnly / Write / Destructive / Network
  │   → 与当前权限级别对比
  │
  ├── ④ sed 表达式校验
  │   检测 sed 命令中的危险模式 → 校验正则有效性
  │
  ├── ⑤ 可疑路径检测
  │   检测 ../ 逃逸、/etc/passwd 等敏感路径
  │
  └── ⑥ 命令语义分类
      返回命令分类标签 → 影响后续权限判定
```

### 5.2 命令语义分类

```rust
enum CommandCategory {
    ReadOnly,      // cat, grep, ls, find, head, tail, wc, ...
    Write,         // echo >, touch, mkdir, cp, mv, ...
    Destructive,   // rm, rmdir, format, dd, ...
    Network,       // curl, wget, nc, ssh, ...
    Privileged,    // sudo, su, chown, chmod, ...
    Unknown,
}

fn classify_command(command: &str) -> CommandCategory {
    let cmd = command.trim().split_whitespace().next().unwrap_or("");

    const READONLY: &[&str] = &["cat", "grep", "ls", "find", "head", "tail", "wc", "file", "stat", "du", "df"];
    const DESTRUCTIVE: &[&str] = &["rm", "rmdir", "dd", "mkfs", "shred"];
    const NETWORK: &[&str] = &["curl", "wget", "nc", "ssh", "scp", "rsync"];
    const PRIVILEGED: &[&str] = &["sudo", "su", "chown", "chmod", "mount"];

    if PRIVILEGED.contains(&cmd) { return CommandCategory::Privileged; }
    if DESTRUCTIVE.contains(&cmd) { return CommandCategory::Destructive; }
    if NETWORK.contains(&cmd) { return CommandCategory::Network; }
    if READONLY.contains(&cmd) { return CommandCategory::ReadOnly; }

    // 检查管道/重定向
    if command.contains('>') || command.contains(">>") {
        return CommandCategory::Write;
    }

    CommandCategory::Unknown
}
```

## 七、信任解析器

参考 claw-code `trust_resolver.rs`：

### 7.1 信任策略

```rust
enum TrustPolicy {
    AutoTrust,          // 自动信任
    RequireApproval,    // 每次需审批
    Deny,               // 禁止
}

struct TrustResolver {
    trusted_roots: Vec<PathBuf>,          // 信任的根目录
    trust_patterns: Vec<GlobPattern>,     // glob 白名单
    deny_patterns: Vec<GlobPattern>,      // glob 黑名单
}

impl TrustResolver {
    fn resolve(&self, path: &Path) -> TrustPolicy {
        // 1. 黑名单优先
        if self.deny_patterns.iter().any(|p| p.matches_path(path)) {
            return TrustPolicy::Deny;
        }

        // 2. 白名单检查
        if self.trust_patterns.iter().any(|p| p.matches_path(path)) {
            return TrustPolicy::AutoTrust;
        }

        // 3. 信任根目录检查
        if self.trusted_roots.iter().any(|r| path.starts_with(r)) {
            return TrustPolicy::AutoTrust;
        }

        // 4. 默认需审批
        TrustPolicy::RequireApproval
    }
}
```

### 8.2 权限继承

```rust
impl OrgPermission {
    fn resolve(agent: &Agent, org: &Organization) -> Self {
        let mut perm = OrgPermission::default();

        // 1. 公司级默认权限
        perm.merge(&org.default_permissions);

        // 2. 部门权限
        if let Some(dept) = org.departments.get(&agent.department) {
            perm.merge(&dept.default_permissions);
        }

        // 3. 角色权限
        if let Some(role) = org.role_templates.get(&agent.role) {
            perm.merge(&role.permissions);
        }

        // 4. Agent 自定义权限
        perm.merge(&agent.custom_permissions);

        // 5. 确保不越权
        perm.max_permission_mode = perm.max_permission_mode
            .min(role.permissions.max_permission_mode);

        perm
    }
}
```

## 九、三原则落地

### 9.1 可观测

| 观测点 | 内容 |
|--------|------|
| 权限审计日志 | 每次权限判定记录：谁、什么操作、什么结果、为什么 |
| 安全事件 | 拦截记录：拒绝的工具调用、越界文件访问、破坏性命令 |
| 沙箱状态 | 当前隔离级别、能力探测结果 |

### 9.2 可治理

| 治理能力 | 实现方式 |
|----------|----------|
| 实时修改权限模式 | 按 Agent 随时调整权限级别 |
| 动态规则调整 | allow/deny/ask 规则热更新 |
| 角色权限模板 | 按角色预设权限，新建 Agent 自动继承 |
| 审批流 | 高风险操作触发审批门控 |

### 9.3 可控风险

| 风险 | 控制 |
|------|------|
| 越权操作 | 四层权限架构 + 工具权限映射，越权自动拦截 |
| 工作区逃逸 | 文件边界检查 + 符号链接检测 |
| 危险命令 | 破坏性命令分类 + 交互式确认 |
| 敏感路径访问 | 目录黑名单 + 信任解析器 |
| 资源耗尽 | 沙箱 CPU/内存/进程数限制 |
