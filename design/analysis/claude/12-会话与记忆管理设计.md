## 一、设计依据

### 1.1 参考来源

| 参考模块 | 核心能力 | Legion 映射 |
|----------|----------|-------------|
| `session.rs` | 消息持久化、版本化序列化、文件轮转（256KB） | 工作记忆持久化 |
| `session_control.rs` | 会话 CRUD、工作区哈希命名空间 | 会话管理控制面 |
| `compact.rs` | 自动压缩、摘要生成、多层合并 | 记忆蒸馏 |
| `summary_compression.rs` | 行规范化、优先级选择、预算控制 | 压缩算法 |
| `usage.rs` | Token 四维计数、模型定价表、累计追踪 | 用量预算 |
| `task_registry.rs` | 线程安全任务注册表 | 任务状态管理 |

### 1.2 关键差异

claw-code 的会话管理面向**单个开发者连续对话**。Legion 需要扩展到：

- **多 Agent 并发** — 每个 Agent 有独立会话
- **任务上下文** — 会话与任务绑定
- **跨任务记忆** — 会话关闭后转化为情景/能力记忆
- **会话审计** — 组织级可观测性要求

## 二、会话生命周期

```
┌──────────────────────────────────────────────────────────────┐
│                    会话生命周期                               │
│                                                              │
│  Created (Agent 创建时)                                       │
│    │                                                         │
│    ▼                                                         │
│  Active (Agent 执行任务中)                                     │
│    │                                                         │
│    ├── 每次 turn 追加消息                                     │
│    ├── token 超出阈值 → Compacting                            │
│    │       │                                                  │
│    │       ▼                                                  │
│    │   CompactionDone (摘要 + 保留消息)                       │
│    │       │                                                  │
│    │       └──→ Active (继续)                                 │
│    │                                                         │
│    ├── 任务完成 → ExperienceExtracting                        │
│    │       │                                                  │
│    │       ▼                                                  │
│    │   Archived (归档保留)                                    │
│    │                                                         │
│    └── 任务中断 → Paused (可恢复)                             │
│                                                              │
│  Terminated (Agent 销毁时)                                    │
│    └── 所有会话归档 → 过期清理                                │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 文件轮转

参考 claw-code 的轮转策略：

```rust
const ROTATE_AFTER_BYTES: u64 = 256 * 1024;  // 256KB
const MAX_ROTATED_FILES: u32 = 3;             // 保留最近 3 个备份

impl SessionStore {
    fn persist_message(&self, session: &Session, message: &ConversationMessage) {
        let path = self.session_path(&session.session_id);
        let json_line = format!("{}\n", serde_json::to_string(&message).unwrap());

        // 增量追加 JSONL
        self.append_to_file(&path, &json_line);

        // 检查是否需要轮转
        if path.metadata().map(|m| m.len()).unwrap_or(0) > ROTATE_AFTER_BYTES {
            self.rotate_session_file(&session.session_id);
        }
    }

    fn rotate_session_file(&self, session_id: &str) {
        // 删除最旧的备份
        let oldest = self.session_dir().join(format!("{session_id}.{MAX_ROTATED_FILES}.jsonl"));
        let _ = std::fs::remove_file(&oldest);

        // 轮转：.2 → .3, .1 → .2, current → .1
        for i in (1..MAX_ROTATED_FILES).rev() {
            let from = self.session_dir().join(format!("{session_id}.{i}.jsonl"));
            let to = self.session_dir().join(format!("{session_id}.{i+1}.jsonl"));
            let _ = std::fs::rename(&from, &to);
        }

        let current = self.session_path(session_id);
        let backup = self.session_dir().join(format!("{session_id}.1.jsonl"));
        let _ = std::fs::rename(&current, &backup);
    }
}
```

### 4.3 兼容加载

参考 claw-code 的加载优先级：

```rust
impl SessionStore {
    fn load_session(&self, session_id: &str) -> Result<Session> {
        let path = self.session_path(session_id);

        if !path.exists() {
            // 尝试从备份恢复
            return self.try_recover_from_backup(session_id);
        }

        let content = fs::read_to_string(&path)?;

        // 优先级 1：完整 JSON（有 messages 键）
        if let Ok(session) = serde_json::from_str::<Session>(&content) {
            if !session.messages.is_empty() {
                return Ok(session);
            }
        }

        // 优先级 2：JSONL 逐行解析
        self.parse_jsonl_session(&content)
    }
}
```

### 5.2 会话恢复

```rust
impl SessionManager {
    async fn resume_session(&mut self, session_id: &str, agent: &Agent) -> Result<Session> {
        let session = self.store.load_session(session_id)?;

        // 1. 注入恢复提示
        let resume_prompt = format!(
            "正在恢复之前的会话 {session_id}。\n\
             会话创建于：{}\n\
             消息数量：{}\n\
             上次状态：{:?}\n\
             继续执行未完成的工作。",
            session.created_at_ms,
            session.messages.len(),
            session.task_status,
        );

        // 2. 标记会话为活跃
        self.active_sessions.insert(session_id.to_string(), session.clone());

        // 3. 发送恢复通知
        agent.send_system_message(&resume_prompt);

        Ok(session)
    }
}
```

## 六、记忆系统集成

### 6.1 工作记忆 → 情景记忆 转化

任务结束时自动提取：

```rust
impl MemoryBridge {
    async fn consolidate(&self, session: &Session) -> Vec<EpisodicEntry> {
        let mut entries = Vec::new();

        // 1. 提取关键决策点
        for msg in &session.messages {
            if let Some(decision) = self.classify_as_decision(msg) {
                entries.push(decision);
            }
        }

        // 2. 提取错误与修复
        for msg in &session.messages {
            if let Some(lesson) = self.extract_error_lesson(msg) {
                entries.push(lesson);
            }
        }

        // 3. 生成任务摘要
        let summary = self.summarize_session(session);

        entries.push(EpisodicEntry {
            id: format!("ep-{}", Uuid::new_v4()),
            task_summary: summary,
            task_type: self.classify_task_type(session),
            quality_score: self.evaluate_session_quality(session),
            created_at: Utc::now(),
            retention_days: self.compute_retention(session), // 重要任务保留更久
        });

        entries
    }

    fn compute_retention(&self, session: &Session) -> u32 {
        // 重要任务 → 180 天
        // 常规任务 → 90 天
        // 琐碎任务 → 30 天
        match session.task_status {
            TaskStatus::Completed { quality_score } if quality_score > 0.8 => 180,
            TaskStatus::Completed { .. } => 90,
            _ => 30,
        }
    }
}
```

### 6.2 记忆检索（注入上下文）

```rust
impl MemoryBridge {
    fn retrieve_relevant(
        &self,
        agent: &Agent,
        current_task: &Task,
        limit: usize,
    ) -> Vec<MemorySnippet> {
        let mut results = Vec::new();

        // 1. 检索同类任务的经验
        results.extend(
            self.episodic_store
                .search_by_task_type(&current_task.task_type, limit / 2)
        );

        // 2. 检索使用相同工具的经验
        results.extend(
            self.episodic_store
                .search_by_tools(&current_task.required_tools, limit / 4)
        );

        // 3. 检索能力记忆（最佳实践）
        results.extend(
            self.capability_store
                .search_by_domain(&current_task.domain, limit / 4)
        );

        // 4. 按相关性排序
        results.sort_by(|a, b| b.relevance.cmp(&a.relevance));
        results.truncate(limit);

        results
    }
}
```

## 七、三原则落地

### 7.1 可观测

| 观测点 | 内容 |
|--------|------|
| 会话列表 | Agent 的所有会话（活跃/归档），含状态和费用 |
| 消息审计 | 完整对话历史，支持搜索和过滤 |
| 压缩记录 | 每次压缩的时间、摘要、移除消息数 |
| 记忆提取日志 | 从会话提取了哪些经验、质量评分 |

### 7.2 可治理

| 治理能力 | 实现方式 |
|----------|----------|
| 会话审计 | 管理员可查看任何 Agent 的会话历史 |
| 会话删除 | 按需删除特定会话或按时间修剪 |
| 记忆审核 | 提取的经验需标记"AI 生成 - 待审核" |
| 手动恢复 | 从任意历史会话恢复 Agent 状态 |

### 7.3 可控风险

| 风险 | 控制 |
|------|------|
| 存储膨胀 | 256KB 轮转 + 3 备份上限 + 定期修剪 |
| 上下文窗口溢出 | 自动压缩阈值（默认 100K tokens） |
| 敏感信息持久化 | 压缩摘要过滤敏感字段 |
| Agent 记忆退化 | 过长会话自动压缩保留核心信息 |
| 会话重复执行 | 原子任务锁定防止重复恢复 |
